# 小投 前端技术栈

> 适用于 **小投（JobCourier）**。前端是一套**手写的 React 单页应用**（TypeScript），源码在 `frontend/`，
> 构建产物由 FastAPI 后端在 **8000 端口**一并伺服。前后端同源、只有一个端口；浏览器访问
> `http://127.0.0.1:8000` 即可，没有独立的桌面壳，也不依赖任何代码生成工具。

---

## 一、总体架构

```
┌───────────────────────────────────────────────┐
│  前端源码 frontend/src（TypeScript）            │
│  pages/      五个页面组件                       │
│  pages/config/  配置中心的类型与表单零件         │
│  components/ 业务弹窗（查企业 / 简历定制）       │
│  Shell.tsx   页面外壳（顶栏 + 标题栏）           │
│  ui.tsx      基础组件（按钮/开关/弹窗/多选…）    │
│  store.tsx   运行时上下文（WebSocket + 快照）    │
│  api.ts      类型化 HTTP 客户端                  │
│  theme.ts / theme.css  主题开关 + 设计令牌       │
└──────────────────┬────────────────────────────┘
                   │ tsc -b && vite build
┌──────────────────▼────────────────────────────┐
│  构建产物 frontend/dist/（index.html + assets）  │
└──────────────────┬────────────────────────────┘
                   │ WebSocket（/ws）+ HTTP（/api）
┌──────────────────▼────────────────────────────┐
│  FastAPI 后端（uvicorn，8000 端口，同进程）      │
│  StaticFiles 伺服 dist/，兜底路由回退 index.html │
│  投递引擎 / 自动回复 / SQLModel + SQLite        │
└───────────────────────────────────────────────┘
```

后端把 `frontend/dist` 挂在同一进程的 8000 端口上，所以生产形态下**没有跨域、没有第二个端口**；
只有本地开发才会单独跑 Vite（见第二节）。

## 二、构建与运行

```powershell
# 一键启动（项目根目录，首次会自动构建前端）
.\start-jobcourier.cmd

# 或者手动来：
uv sync
cd frontend; npm ci; npm run build; cd ..
$env:PYTHONUTF8 = "1"
uv run python -m job        # 启动本地服务并自动打开浏览器
```

- 前端 `npm run build` = `tsc -b && vite build`，产物写到 `frontend/dist/`。
- 后端启动时用 `StaticFiles` 挂载 `dist/assets`，其余路径兜底返回 `dist/index.html`（SPA 路由）。
- 只改后端 `job/`：重启进程即可。改动 `frontend/`：必须重新 `npm run build` 才会生效。
- 中文 Windows 必须设置 `PYTHONUTF8=1`，否则 Python 读 UTF-8 文件会 GBK 解码崩溃。

前端单独开发（前后端分离调试）：

```powershell
cd frontend
npm run dev      # Vite 开发服务器，5173 端口
```

`vite.config.ts` 把 `/api` 与 `/ws` 代理到后端（默认 `http://127.0.0.1:8000`），所以 dev 模式下
也只需要后端跑在 8000。后端端口 / 地址的**唯一真源**是 `job/api/net.py`，可用环境变量
`JOB_COURIER_HOST` / `JOB_COURIER_PORT` 覆盖；Vite 的代理读的是同一组变量，避免前后端各写一个端口。
dev 服务器开了 `strictPort: true`——5173 被占用时直接报错，而不是悄悄换端口导致代理指向错乱。

## 三、技术选型

| 技术 | 版本 | 作用 |
|---|---|---|
| React / react-dom | ^19.1 | UI 运行时（函数组件 + Hooks） |
| react-router-dom | ^7.6 | 前端路由：`/`、`/jobs`、`/messages`、`/stats`、`/config` |
| TypeScript | ~5.8 | 全量类型；`tsc -b` 作为构建第一步做类型检查 |
| Vite | ^6.3 | 构建与开发服务器（`@vitejs/plugin-react`） |
| Tailwind CSS | ^4.1 | 原子类样式（CSS-first，经 `@tailwindcss/vite` 接入，无 `tailwind.config.js`） |
| Radix UI 原语 | — | `react-dialog` / `react-switch` / `react-select` / `react-checkbox` / `react-menu` / `react-tooltip`，只取无样式行为，样式自己写 |
| lucide-react | ^0.511 | 图标库 |
| sonner | ^2.0 | 右下角 toast 通知（跟随当前主题） |

> 说明：**没有** Emotion / styled-components 之类的 CSS-in-JS，也没有图表库——数据页的条形图是
> 普通 `div` + 背景色 + CSS 动画手绘的（见 `theme.css` 里与 `.g-track` 相关的规则）。

## 五、样式与主题体系

1. **设计令牌**（`frontend/src/theme.css`）
   - 日间主题「纸与墨」：暖纸底 `--paper #f3f0e9`、卡片 `--sheet #fffefa`、墨色文字 `--ink #17130e`；
     主色是**靛青 `--accent #0f6f6c`**（配 `--accent-hi / --accent-deep / --accent-soft / --accent-line`）。
   - 夜间主题「星港」：挂在 `[data-theme="dark"]` 下，深空底 `--paper #070a12`，
     主色换成**冰蓝 `#22d3ee`**，语义色整体提亮到深底上仍可读。
   - 语义色 `--good / --warn / --bad`，薪资专用色 `--salary`，圆角 `--r-*`、阴影 `--sh-*`、
     字号 `--fs-*`、缓动 `--ease`、层级 `--z-*` 等都在同一份令牌里。
   - 主题切换见 `theme.ts`：把 `data-theme` 写到 `<html>`，同步 `color-scheme` 与 `<meta name="theme-color">`；
     选择存 localStorage（键 `gj-theme`）。`index.html` 里有一段内联脚本在首帧前先定主题，避免夜间闪白。
2. **Tailwind 原子类**：布局、间距、排版优先用 Tailwind class（如 `flex`、`rounded-2xl`、`text-sm`）。
3. **内联样式**：需要精确颜色 / 尺寸 / 动画时直接用 `style={{ ... }}`，颜色尽量引用 `theme.css`
   的令牌或 `ui.tsx` 导出的常量（`ACCENT / INK / TEXT / MUTED / BORDER / SURFACE / SALARY …`）。
4. **类名前缀约定**：结构组件统一 `g-`，排版统一 `t-`。
   - 结构：`g-shell / g-top / g-top-inner / g-brand / g-brandmark / g-navlink / g-container / g-scroll /
     g-card / g-sect / g-in / g-divided / g-field / g-input / g-input-sm / g-combo* / g-menu / g-menu-item /
     g-btn* / g-chip / g-row / g-thead / g-conv / g-salary / g-avatar / g-dot / g-empty / g-modal /
     g-overlay / g-skel / g-well / g-grain / g-rule / g-col / g-fill / g-body* / g-skip / g-track` 等
   - 排版：`t-display / t-h1 / t-h2 / t-body / t-label / t-meta / t-micro / t-mono / t-num / t-eyebrow`
5. **动效工具类**（`theme.css` 底部，组件用 `className` 引用）
   - `g-in`：入场错峰上浮（`g-rise`）；`g-in-slide`：侧向滑入（`g-slide-in`）
   - `g-breathe` / `g-pulse`：呼吸式明暗（连接遮罩的指示条、运行中的状态点）
   - `g-spin`：旋转，给 lucide 的 `Loader` 之类图标套用
   - `g-lift`：卡片悬停浮起；`g-skel`：骨架屏流光
   - 已声明 `@media (prefers-reduced-motion: reduce)`，系统开启「减少动态效果」时统一压缩动画时长与过渡。

## 六、状态与前后端通信

- **WebSocket `/ws`**：运行状态与日志的主通道，由 `store.tsx` 的 `RuntimeProvider` 统一维护：
  - 收到 `snapshot` / `status` 消息时，按白名单字段提取运行时快照（投递状态、计数、目标城市等）写入 context；
  - 收到 `log` 消息时追加到日志流（保留最近 200 条）；
  - `analyze_done` / `company_step` / `company_done` 等页面级事件，通过 `window` 自定义事件
    `gj:event` 广播给对应页面监听；
  - **断线自动重连采用指数退避**：1s 起、每次翻倍、封顶 30s，重连成功后重置为 1s；
  - 连接状态（`connecting / open / closed`）与「本次会话是否连上过」（`everConnected`）由
    `useRuntime()` 暴露，驱动 `ConnectionGate` 遮罩：没连上过显示「正在启动」，掉线后显示「正在重连」；
  - 后台偶尔推来非 JSON 文本，解析失败会被吞掉，不连累整条通道。
- **HTTP `/api/**`**：常规读写、上传、导出走 `api.ts`，返回 JSON；失败抛 `Error(detail)`，调用方弹 toast。
  - 默认 15s 超时；`/api/analyze`、`/api/tailor`、`/api/company`、`/api/llm/`、`/api/reply/`
    这类要跑采集或大模型的接口放宽到 120s。超时提示「请确认后台服务是否在运行」。
- **上传**：简历文件用 `FormData` 直接 POST（见 `api.upload`），后端解析 PDF / Word / 图片。
- **导出**：浏览器端直接触发文件下载。

## 七、开发注意事项

1. **不要手改 `frontend/dist/`** —— 它是构建产物，下次 `npm run build` 会被覆盖。
2. **类型先行**：`npm run build` 第一步就是 `tsc -b`，类型不过构建就失败；新增 API 时同步更新
   `api.ts` 里的类型。
3. **基础组件统一在 `ui.tsx`**：按钮、弹窗、多选等都从这里取，避免各页面各写一套；配置中心的
   表单零件放 `pages/config/parts.tsx`，类型放 `pages/config/types.ts`。
4. **样式常量统一来源**：颜色优先引用 `theme.css` 的令牌或 `ui.tsx` 的常量，别到处写死色值。
5. **动效克制**：入场 / 悬停动效全部纯 CSS 且不影响可读性——动画元素切忌从 `opacity: 0`
   起步承载关键信息（截图 / 降速环境会显得空白）。
6. **页面尽量薄**：页面组件只做组装与调用，业务状态放在后端与 `store`，前端不重复持有业务真相。
